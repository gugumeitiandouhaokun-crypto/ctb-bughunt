# 高质量找 bug 测试用例方法论

核心心法：**用例的价值 = 覆盖的规则/状态/路径数量 × 每条断言的精确度**，两者缺一不可。
"小场景多而全"远不如"超大密集多对象、循环重、合法与非法混合、逐条精确断言"。松散的小场景只能命中表层 bug，复杂度要靠"对象数 × 操作数 × 循环圈数"与状态叠加撑起来。

## 一、目标与衡量标准（按优先级）

1. 检出的 bug 数量（去重）最大，单个用例覆盖尽量多的 bug。
2. 所有用例在无 bug 版本上全部通过，否则用例无效。
3. 准确率：在无 bug 版本上失败的用例即误报，必须为零。
4. 代码质量扣分最少（以判题返回的扣分项为准）。

## 二、本平台约束（与通用方法论不同之处）

- 只能提交 `testaw.py` 与 `udpunittest.py`。"多个用例文件取并集"改为：同一个 `udpunittest.py` 的 `MyTestCase1` 中写多个 `test_*` 方法，每个方法覆盖不同的规则/状态/路径组合。
- 每个用例方法必须有 `@timeout(global_default_timeout)`，且 300 秒内完成。用探针测出的单条命令平均耗时估算规模，`ctb.py local` 输出的每个用例耗时应留出余量（建议 250 秒以内）；超出时拆成多个方法。
- 每个用例开始时被测系统已复位（框架在每个用例结束后发送 `init()`），用例之间不能依赖状态。
- 可以在本地运行无 bug 版本：主体用例用 `ctb.py record` 录制生成，场景由生成脚本描述，期望值来自真实返回，逐条精确断言的成本接近于零；精力集中在场景设计上。
- 录制生成的是数据表 + 统一执行函数，代码量与步骤数无关；手写用例同样用数据表 + 循环 + 辅助函数表达，不要平铺复制大段相似代码。代码质量规则以第一次 `ctb.py run` 返回的扣分项为准，并记入 `notes/复盘.md`。
- 可以反编译无 bug 版本的 jar。源码用来提出规则、分支与边界的假设并指导步骤设计；覆盖率报告指出哪些业务分支还没被步骤执行到。手写断言中的数值必须经探针确认。
- 只用 Python 标准库，兼容 Python 3.8。

## 三、整体流程

### 第 0 步：摸清工程与约束（先读后写）

- 通读题目描述、接口输入输出说明、返回格式、已有样例代码与框架文件。
- 明确本地运行方式与判定方法：以日志 `Ran N tests ... OK` 为准，不看进程退出码。
- 明确需要探针确认的硬性约束：
  - 输入合法性边界：标识符格式与长度、名称与口令规则、数值范围、数量上限、时间范围。
  - 时间规则：全局时钟是否只能单调向前；数值是否在跨越某个周期边界（如自然日、自然月、自然年）时重置。
  - 资源容量：同类资源的数量上限、多个对象能否同时占用、是否存在争用。
  - 每次调用的返回是否都需要断言（只发命令不断言的调用无检出价值）。

### 第 1 步：小探针摸清接口

- 确认每个接口的返回格式、成功与各类失败的返回码与文本、系统生成标识（编号、会话等）的形态、时间与容量边界。
- 从反编译源码读出规则、分支条件与常量，用探针一次性验证多个假设，减少探针轮数。
- 每条结论写入 `notes/数值模型.md`，注明来源探针记录；记下单条命令耗时，估算每个测试能容纳的步骤数。

### 第 2 步：用生成脚本描述超大密集场景并录制

- 按第四、五节的规模锚点与多对象骨架写生成脚本，对象 × 轮次 × 参数取值用循环展开，合法与非法交错。
- 系统生成的标识用捕获变量传递给后续步骤，使返回可模板化断言而不是退化为只断言返回码。
- `ctb.py record --gen ... --dry-run --coverage` 反复迭代：
  - 命令分布：每个命令都应同时出现成功与失败返回码，不同返回数量应随数据形态增多；
  - 覆盖率：部分覆盖与未执行的业务方法对照源码找出未走到的分支，补对应步骤；
  - 两轮不一致清单：逐条处理，尽量通过捕获变量纳入模板。
- 覆盖不再提升后正式录制写入。

### 第 3 步：补充手写断言并本地验证到全部通过

- 录制断言证明"与无 bug 版本一致"；公式、累计关系、跨对象关系等需要表达推导的断言，用手写用例补充，数值先探针确认。
- `ctb.py check` 后 `ctb.py local`，失败时用探针捕获实际值，判断是模型错还是用例错，修正后重跑，直到全部通过。
- 不允许通过放宽断言（改成包含判断、删断言）来凑通过，除非该值经探针确认确实不可预判。

### 第 4 步：调试判题并复盘

- `ctb.py run` 查看 bug 检出表，结合覆盖率报告分析未命中的 bug 缺哪类规则、状态或路径，据此补下一轮步骤（见第八节）。

## 四、单用例规模锚点（底线）

- 至少 10 个独立业务对象，彼此状态独立、可叠加。
- 单用例操作数至少 100，越多越好，逼近数百（受 300 秒上限约束）。
- 重度循环：多段升级/累积循环、遍历全部条目/类型、重复执行同一业务单元以叠加状态。
- 合法与非法混合：每个循环/阶段都穿插可预判的失败分支（越权、参数非法、超限、重复操作、状态不允许、受限名单）。
- 逐条精确数值断言：能精确计算的绝不只做包含/结构断言。

## 五、多对象设计骨架

适用于"每个对象有独立的累计值/等级/状态"的系统：

1. 对象独立化：每个对象有自己独立的账户/身份与数据，自身状态完全可推算、可精确断言。
2. 等级/状态轮转：让不同对象停留在不同等级或状态（含受限、冻结、注销等），形成"多对象 × 多状态"的组合。
3. 循环推进 + 分段结算：用循环把对象推进到目标等级，每段都精确断言累计值，精确建模跨段结算公式。
4. 遍历条目/类型：在同一等级/状态下遍历所有可选条目，逐一断言计算结果。
5. 精确数值模型：把探针确认的公式写成 `testaw.py` 中的纯函数（例如 实际值 = 基础值 × 系数、产出 = 向下取整(实际值 × 比例)、累计 = 各段之和），扩展更多对象只需套公式。
6. 非法分支混合：错误金额、越权操作、超限、重复操作、受限状态下的操作，每种都预判返回码与返回文本。

### 时间与资源排布（高危区，务必先探针确认）

- 全局时钟只能单调向前时，多个对象的时间线要用循环按序推进，不能跳回过去。
- 数值可能跨周期边界重置时，先探针确认边界行为，再排期，避免累积被意外清零。
- 资源充足时多个对象可以时间重叠；资源有限时错开排布。以探针确认的容量为准。

## 六、断言策略

- 每一步都断言：录制默认对每条命令的整条返回做精确断言；系统生成的标识用捕获变量做模板断言；只有两轮录制都无法稳定的返回才退到只断言返回码。
- 手写断言时，能精确数值就精确数值；只有确实不可预判的值，才退到格式/关系/包含断言，并把取到的值用于后续步骤。
- 精确断言分三层（步骤设计时确保三层都有对应的查询步骤）：
  1. 单步精确值：执行后的累计值 = 执行前 + 本步产出；结算值 = 公式值。
  2. 累积精确值：多段/多轮后的总值 = 各步之和，最能体现模型能力。
  3. 状态精确值：等级、开关、归属、可用数量等状态，用查询接口精确断言。
- 状态变化后要有查询断言，让内部状态的差异暴露在返回值里。
- 宁可多断言，不可漏断言：少一条精确断言可能就漏一个 bug。

## 七、硬性纪律

1. 不删改平台既有文件（测试框架、`main` 段、配置）；探针用 `ctb.py probe`，临时文件用完即删。
2. 断言数值来自录制或探针，禁止凭感觉写死；不手工修改录制标记内的内容。
3. 每次改动先本地验证，保持无 bug 版本全部通过后再调试或提交。
4. 提交前确认没有 `_probe*`、`_fix*`、`_find*` 残留（`ctb.py check` 会拦截）。
5. 先出一个超大用例验证方法论与数值模型，再扩展为多个用例方法。
6. 无 bug 版本全部通过但退出码非 0 属正常，以日志为准。

## 八、复盘循环

每次 `ctb.py run` 后，在 `notes/复盘.md` 记录得分、检出数、未检出的 bug 编号、当前覆盖率（`notes/coverage/history.md` 最后一行）与推测缺口，然后按缺口补充：

- 业务方法未执行或部分覆盖：对照反编译源码中未走到的分支条件，补满足条件的步骤。
- 某条规则未覆盖：补覆盖该规则的场景。
- 缺非法分支：补越权、参数非法、超限、重复、受限状态等失败分支。
- 数据形态单一（命令分布中不同返回很少）：补不同等级、条目、边界、叠加方式。
- 状态叠加不够深：加大循环圈数、对象数，延长状态链。
- 覆盖率已高但仍有未检出：bug 往往在已执行代码的数值或顺序细节上，加密同一路径上的不同参数与状态组合，增加查询断言。
- 代码质量扣分：按扣分项重构（抽辅助函数、数据表驱动）。

每轮都朝"更高数量 × 更精确"演进，不重复老套路。

## 九、交付物

- `answer/testaw.py` 与 `answer/udpunittest.py`：多个带超时装饰器的用例方法（录制生成 + 手写补充）。
- `notes/steps/` 下的生成脚本，可随时重录。
- 本地验证记录：`notes/local_last.txt` 显示全部通过；`notes/coverage/history.md` 记录覆盖率变化。
- `notes/复盘.md` 中每个用例一句话定位：场景主题、覆盖的等级/状态组合、主要非法分支、总操作数。
