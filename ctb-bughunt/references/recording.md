# 录制与覆盖率

录制把"写断言"变成"写步骤"：只描述要发送的命令序列，期望值由无 bug 版本的真实返回自动生成；覆盖率告诉你这些步骤执行到了多少业务代码。两者配合，用最少的人工把用例做大、做密、做准。

## 一、步骤文件

### 约束

- UTF-8 文本，每行一条，首尾空白忽略；空行与 `#` 开头的行忽略。
- `== <测试名> ==` 开始一个测试方法。测试名以 `test` 开头，只含 ASCII 字母、数字、下划线；同一文件内不可重复，也不可与 `udpunittest.py` 中其他方法重名。
- 第一个 `== ... ==` 之前不能出现命令；每个测试至少一条命令。
- 普通行是一条原样发送的命令。
- `$变量 = 命令`：发送命令，把返回中第一个 `:` 之后的全部文本存入变量；返回中没有 `:` 时存空串。
- `$变量/正则/ = 命令`：发送命令，把正则第 1 个分组（无分组时取整体匹配）存入变量；不匹配时存空串。
- `${变量}` 在之后的命令中引用变量。变量只在当前测试方法内有效，且必须先捕获后引用（解析时校验）。
- 命令里不要带多余空格（`check` 会对含空格的命令字面量告警）。
- 每个测试开始前会发送 `init()`，测试之间不共享状态；测试按名称排序执行，与 unittest 的执行顺序一致。
- 单个测试的命令总耗时必须远小于 300 秒；录制报告给出每个测试的耗时，超过 250 秒要拆分。

### 示例

```
== test_01_multi_object ==
create_obj(A001,10)
create_obj(A002,20)
use_obj(A001,3)
use_obj(A002,25)
query_obj(A001)
query_obj(A002)
$sid = open_session(A001)
close_session(${sid})
$cnt/total=(\d+)/ = stat_obj(A001)

== test_02_illegal_input ==
create_obj(A001,10)
use_obj(A001,0)
use_obj(A001,-1)
use_obj(A999,1)
```

## 二、生成脚本

### 约束

- 规模大的场景用 Python 脚本生成步骤：脚本的标准输出就是步骤文件内容，格式同第一节。
- 脚本放在 `notes/steps/` 下，只用标准库；由 `ctb.py record --gen` 在工作目录下执行，输出另存为 `notes/steps/<名称>.steps.txt`。
- 录制名称默认取脚本/文件名（不含扩展名），只能含 ASCII 字母、数字、下划线；同名再次录制会整块替换上次的结果，不影响其他录制与手写用例。
- 一个脚本可以输出多个测试；按场景主题拆成多个脚本，便于单独重录。
- 用数据与循环描述场景：对象列表 × 操作轮次 × 参数取值（合法边界、非法值），合法与非法交错。

### 示例

```python
OBJECTS = ["A%03d" % i for i in range(1, 13)]


def emit(line):
    print(line)


emit("== test_01_multi_object ==")
for i, obj in enumerate(OBJECTS):
    emit("create_obj(%s,%d)" % (obj, 10 + i))
for rnd in range(3):
    for i, obj in enumerate(OBJECTS):
        emit("use_obj(%s,%d)" % (obj, 1 + i + rnd * 5))
    for obj in OBJECTS:
        emit("query_obj(%s)" % obj)

emit("== test_02_illegal_input ==")
emit("create_obj(A001,10)")
for value in (0, -1, 1, 100, 101):
    emit("use_obj(A001,%d)" % value)
```

## 三、录制与断言生成

### 约束

- 录制在无 bug 版本上进行，同一进程内连续执行两轮：第 A 轮从全新启动开始，第 B 轮紧接着再执行一遍（每个测试前仍发 `init()`）。
- 每一步按两轮返回生成断言：
  - 两轮一致：精确断言整条返回。
  - 不一致，但把返回中出现的已捕获变量值替换为 `${变量}` 后两轮都能还原：模板断言，运行时用当次捕获的值填充后精确比较。
  - 仍不一致：只断言返回码（第一个 `:` 之前的部分），并列入录制报告的"两轮不一致"清单。
- 只断言返回码的步骤要逐条查看：常见原因是返回中含有时间、随机值、或未被 `init()` 复位的计数。能通过捕获变量（`$变量 = ...`）把可变部分纳入模板的，修改步骤后重录；确实不可预判的，保持现状或改为手写的格式/关系断言。
- 录制结果写入：
  - `answer/testaw.py`：运行时块（`run_steps`，只写一次）与数据表块 `STEPS_<测试名>`；
  - `answer/udpunittest.py`：每个测试一个 `@timeout(global_default_timeout)` 方法，调用 `testaw.run_steps(self, testaw.STEPS_<测试名>)`，插在 `# 提示：联调函数` 注释之前。
- 写入区域以 `# ==== ctb-record ... begin/end ====` 标记包围，不要手工修改标记内的内容（重录会覆盖）；需要手工调整的断言写成标记外的独立用例。
- `udpunittest.py` 必须已有 `import testaw`、`from timeout import timeout` 与 `global_default_timeout`，否则不做任何修改并报错。
- 录制写入后自动执行 `check` 与 `local`；失败时按 `local` 输出的"step N: 命令 expect 期望 actual 实际"定位。
- 断言失败消息格式：`step <序号>: <实际发送的命令> expect <期望> actual <实际>`，序号从 1 开始，对应步骤文件中该测试的第几条命令。
- 数据表的代码质量以判题返回的扣分项为准；如被扣分，按扣分项调整表的组织方式并记入 `notes/复盘.md`。

### 数据表示例

```python
STEPS_test_01_multi_object = (
    ('create_obj(A001,10)', 'E000:Success'),
    ('use_obj(A001,3)', 'E000:7'),
    ('open_session(A001)', 'E000:${sid}', 't', 'sid'),
    ('close_session(${sid})', 'E000:Success'),
    ('stat_obj(A001)', 'E000:total=7', 'e', 'cnt', 'total=(\\d+)'),
    ('tick()', 'E000:1712', 'p'),
)
```

## 四、录制报告（`notes/record/<名称>.md`）

### 约束

- 汇总：测试数、步骤数、精确/模板/仅返回码断言的条数；`init()` 未返回成功的测试。
- 测试表：每个测试的步骤数与录制耗时，超过 250 秒标注需拆分。
- 命令分布：每个命令的调用次数、返回码分布、不同返回的数量。用它检查步骤是否有效：
  - 某命令几乎全是失败返回码：前置状态没搭好，合法路径没走到；
  - 某命令没有任何失败返回码：非法分支没覆盖；
  - 某命令"不同返回"只有 1 个：数据形态单一，补不同参数、不同状态下的调用。
- 两轮不一致清单：测试名、第几步、步骤文件行号、两轮返回。

## 五、覆盖率

### 约束

- `ctb.py record ... --coverage` 统计本次录制执行到的代码；`ctb.py coverage` 带覆盖率跑一次完整的 `local`（含手写用例）。
- 只统计业务类（排除常见三方库）；报告写入 `notes/coverage/<时间>.md`，摘要追加到 `notes/coverage/history.md` 并给出与同一来源（同名录制或 `local`）上次结果的差值。
- 报告内容：行/分支/方法覆盖率；按类列出（未覆盖行多的在前）；未执行的方法；部分覆盖的方法（未覆盖行 + 分支多的在前）。
- 方法后的 `L<行号>` 是原始源码行号，与反编译源码的行号不对应；按"类名.方法名"在 `decompiled/` 中定位。
- 框架、网络、日志等基础设施类的低覆盖与检出无关，关注处理业务命令的类与方法。
- 部分覆盖的业务方法是最直接的补充方向：打开反编译源码，找出未走到的分支条件，构造满足条件的步骤（含非法输入、边界值、特定状态组合）。
- 工作目录路径含空格或非 ASCII 字符且无法转换为短路径时，覆盖率不可用，需换到纯英文路径。

## 六、迭代方式

1. 读 `decompiled/index.md` 与题目描述，确定接口清单与规则。
2. 用少量 `probe` 确认返回格式与标识类返回的形态，决定哪些步骤需要捕获变量。
3. 编写生成脚本，`ctb.py record --gen notes/steps/<名称>.py --dry-run --coverage`。
4. 读录制报告与覆盖率报告，补对象、轮次、状态组合与非法分支，重复第 3 步，直到业务方法的覆盖不再提升、命令分布合理、不一致清单已处理。
5. 去掉 `--dry-run` 正式写入，确认 `check` 与 `local` 通过。
6. 公式、累计关系等需要表达"为什么是这个值"的断言，在标记外手写用例补充，数值仍须探针确认。
7. `ctb.py run` 后按 `references/methodology.md` 第八节复盘，回到第 3 步。
