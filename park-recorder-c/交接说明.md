# C 版本找 bug 用例：交接说明

## 题目版本关系

- A 版本：账户管理（临时账户、会员账户、车辆绑定）与车辆进出管理（入场、出入口管制、出场、停车状态）。
- B 版本：在 A 基础上变更车辆进出规则，新增车位资源管理（车位状态、统计、黑名单）、账户充值（充值、付费、月卡、转让）、计费支付（计费标准、节假日、包月、支付流程）、营收统计。
- C 版本：以 A、B 为基础，新增车位预约与洗车服务。被测 jar 的命令集合为 A、B 全部命令加上：
  - 车位预约：`reserve_space`、`cancel_reserve`、`check_reserve_status`、`query_reserve`
  - 洗车服务：`take_wash_order`、`cancel_wash_order`、`query_wash_status`、`start_wash_service`、`end_wash_service`、`trigger_wash_balance`、`query_wash_queue`
- A、B 的规则作为理解 C 的基础；bug 更多出现在 C 文档中更新的部分（新增子系统，以及新增功能与 A、B 已有功能交互的规则），用例设计与覆盖率分析以这些部分为重点。
- `题目/题目描述_C.md` 已合并 A、B 全部需求（B 的需求变更直接写入对应章节），章节编号：3.1 账户管理、3.2 车辆进出、3.3 车位资源管理、3.4 账户充值、3.5 计费支付、3.6 营收统计；接口为 4.1 可测试性、4.2 操作（4.2.1~4.2.17）、4.3 查询（4.3.1~4.3.4）、4.4 检查（4.4.1~4.4.4）。B 版本工作中所说的“3.3 账户充值子系统”对应本文档 3.4。
- 车位预约与洗车服务的需求描述暂缺；拿到后补入第 3、4 章，再列出 C 的新增与变更条目。

## 需要按 C 版本 jar 适配的地方

- `oracle.js`：B 版本用到的混淆类名 `com.huawei.tools.h.d`（全局状态，字段 `ce` 车牌→会员、`cd` 会员表、`cg` 在场会话）、`com.huawei.tools.g.a.f`（会话）、`com.huawei.tools.g.b.a.c` 的计费方法 `b(f)` 与 `a(f,long)`。C 版本按反编译结果重新对应。
- `cov33.py`：`PKG`、`TARGETS`、`DESCS` 换成 C 版本目标子系统的类与方法签名。
- `gap33.py`：`PKG`、`TARGETS` 同上。
- `record.py`：`--version C` 默认加载 `scenes_c.py`，`--scenes` 可指定其他模块；`release` 的默认预期按 B 版本返回 `E000:<车位号>`，C 版本不同时修改 `Rec.release`。
- 场景文件不能 import 其他场景文件（会把对方的场景一并注册），共用的辅助函数直接复制到本文件。

## 流程

1. 读题目描述，整理 C 的新增与变更条目；在 `_src` 中从命令分发类（B 版本为 `com.huawei.tools.c.a`）找到新增命令的实现与被调用的内部方法，填入 cov33/gap33 的目标列表。
2. 写场景 `scenes_c<主题>.py`：每个 `@scene('test_cjl_<编号>_<含义>')` 一个测试；步骤中 `want=` 为按规格推测的值，仅用于报告对比。
3. 录制：`python record.py --work _workC --version C --scenes scenes_c<主题> --runs 2 --no-verify`；查看 `_workC\record_report.md` 中“与预期不同”的步骤，区分理解偏差与可疑 bug。
4. 本地运行与覆盖率：`python cov33.py --work _workC`。
5. 缺口分析：`python gap33.py --work _workC`；多轮合并用 `--exec a.exec b.exec`。逐条判断未覆盖分支是否可达：字段只在构造中赋值、成对维护的数据、调用内部即删除的中间状态、参数解析拦截、字符串 switch 哈希分支（前置白名单校验时不可达，无校验时可用同 hashCode 字符串触发）。
6. 交付：`testaw.py` 与 `udpunittest.py` 复制到 `final_C_<主题>/`；新一轮开始前移入 `backup/`。

## 录制器常用接口（场景函数参数 r）

| 接口 | 作用 |
|---|---|
| `r.call(cmd, *args, want=)` | 发送任意命令并记录一行断言 |
| `r.goto(datetime)` / `r.time_pass(unit, n)` | 推进模拟时间 |
| `r.member(phone)` | 注册并激活会员，返回会员号 |
| `r.arrive(plate)` / `r.entry(plate, gate)` | 入场请求，返回 (会话号, 会员号) |
| `r.occupy(sid, space)` / `r.release(sid)` | 占位 / 离位 |
| `r.leave(sid)` / `r.exit(sid, gate)` | 出场请求 |
| `r.status(plate, sid, st)` | 校验车辆状态 |
| `r.due(sid)` | oracle 查询会话应缴信息，`ok` 表示会话仍存在 |
| `r.pay(sid, kind, delta=)` / `r.pay_value(sid, kind)` | 按 oracle 金额缴费 / 取应缴金额 |
| `r.revenue(scope, kind)` / `r.revenue_all(scopes)` | 按 oracle 营收值校验 check_revenue |
| `r.asset(cid)` | 查询会员资产 |

## B 版本经验（C 版本需重新验证）

- 被测程序金额校验容差 0.01：拒绝类探测用 ±0.02，边界用 +0.01。
- 出入场请求返回成功后，放行在 5 秒后的时间推进中发生；放行失败要在推进后查状态才能看到。
- 放行使用的闸机模式在请求时记录，请求后再改模式不影响该车。
- 出场时间字段在会话删除前一刻写入，在场表中不可见。
- 已缴费后继续占位超过 15 分钟才产生补缴；补缴以放行时的月卡与余额状态计算。
- 离位 15 分钟未出场触发强制结算并强制出场；长期滞留 360 小时拉黑、720 小时强制结算。
