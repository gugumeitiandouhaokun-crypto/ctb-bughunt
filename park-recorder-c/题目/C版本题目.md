# 3 子系统功能需求

## 3.1 车位资源管理子系统（刷新）

停车场共配置280个标准停车位，可用于正常停车与车位预约。

新增6个洗车专用工位，独立于标准车位资源池管理，不参与标准车位的预约、满位判定与车位统计，仅用于场内车辆洗车服务。

| **洗车工位类型**   | **数量** | **洗车工位编号** | **兼容说明**      |
| ------------------ | -------- | ---------------- | ----------------- |
| 大型洗车位（WL组） | 1        | WL1              | 支持S、M、L型车辆 |
| 中型洗车位（WM组） | 2        | WM1、WM2         | 支持S、M型车辆    |
| 小型洗车位（WS组） | 3        | WS1、WS2、WS3    | 仅支持S型车辆     |

## 3.2 车位预约子系统

仅新能源车辆支持车位预约功能，燃油车辆不支持预约，仅可到场停放。

### 3.2.1 预约限制

需同时满足以下所有条件，才可发起预约，任一不满足则直接拒绝：

\1. 车牌为激活状态会员账户绑定的车牌；

\2. 车辆为新能源车型；

\3. 车辆处于场外（outpark）状态；

\4. 车辆不在黑名单内。

### 3.2.2 预约车位

\1. 仅状态为空闲的标准车位可被预约，洗车工位、占用/预留状态车位不可预约。

\2. 采用指定车位预约模式，需传入目标车位编号，校验车型兼容与车位状态。

\3. 车型向下兼容：大型车位支持L/M/S型，中型车位支持M/S型，小型车位仅支持S型。

\4. 预约成功后车位状态标记为预留(R)；车辆入场占位成功后，车位状态由R转为占用(U)。

### 3.2.3 预约频次限制

\1. 同一车牌同一时间仅可存在1个有效预约（locked/used状态），已有有效预约时再次预约直接拒绝；

\2. 同一车牌自然日内累计预约次数上限为3次（取消、超时失效均计入），每日00:00自动重置计数。

### 3.2.4 预约取消

车位预约成功后用户可主动取消；若车辆已发起入场流程，则不可取消。取消成功后，预约转为cancel状态，车位恢复为空闲。

### 3.2.5 车位预约单状态迁移

车位预约请求成功返回车位预约单，车位预约单有5种状态：

| **状态标识** | **状态说明**                        | **迁移触发条件**                                             |
| ------------ | ----------------------------------- | ------------------------------------------------------------ |
| locked       | 预约成功，车位为R状态，等待车辆到场 | 1. 车辆入场成功，迁移到used 2. 锁定超30分钟未入场迁移到expired 3. 用户主动取消，迁移到cancel 4. 次日00:00自动迁移到closed |
| used         | 预约车辆按时入场，预约生效          | 车辆成功出场，迁移到closed                                   |
| expired      | 预约30分钟未到场，预约失效          | 次日00:00自动迁移到closed                                    |
| cancel       | 用户主动取消预约                    | 次日00:00自动迁移到closed                                    |
| closed       | 预约生命周期结束                    | 终态，无后续迁移                                             |

### 3.2.6 满位与计费规则

\1. 满位判定：R状态车位从对应车型空闲总数中扣除；预约车辆入场不受自身预约车位的满位限制。

\2. 预约本身不收取任何费用；预约车辆停车费按原系统正常规则执行，无折扣。

## 3.3 洗车服务

园区提供洗车增值服务，仅对场内已入场车辆开放。洗车费用与停车费合并，车辆出场时一并结算。

### 3.3.1 营业时间

每日9:00~18:00提供洗车服务，洗车服务当日结清，不跨天。

\1. 取号时段：每日[9:00~17:00]，非取号时段洗车取号失败；

\2. 过渡时间：当日（17:00~17:30）不可取号，但允许正常排队和叫号；

\3. 在途订单：17:30前已启动的洗车服务可以正常完成。18:00时仍未洗完的订单进入closed状态，正常收取费用；

\4. 排队订单：17:30仍处于排队状态的订单自动转为expired状态，不收取费用，不计入当日车辆申请次数；

\5. 服务结清：18:00所有订单转为closed状态。次日0点无法查询前一天订单，9点之后重新开始新一轮洗车服务。

### 3.3.2 洗车取号

\1. 仅场内车辆可调用take_wash_order申请洗车服务，单车单日限1次；用户主动取消、叫号超时计入当日次数。

\2. 每个工位单日有效订单上限20单（完成订单+在洗订单+排队订单），同时支持1单在洗、6单排队；所有兼容工位无可用容量时，取号失败。

\3. 取号成功生成3位数字服务单号，按自然日从001起顺序编排，次日重置编号。

### 3.3.3 分级洗车派单

洗车取号申请通过后，采用“同组内轮询、全满跨组”原则派单，优先分配与申请车型同类的洗车工位。

\1. 组内严格按工位编号轮询派单，队列内按取号先后顺序排序。

\2. 若组内所有队列饱和（排队6单）或达到有效订单上限（20单）后，则跨组派单，路径如下：

- S型车辆：WS组轮询 → WM组轮询 → WL组轮询
- M型车辆：WM组轮询 → WL组
- L型车辆：仅分配至WL组

### 3.3.4 洗车叫号、开始/结束洗车

派单完成之后，系统对排队的订单进行处理：

\1. 当工位空闲且队列非空时，系统自动对队首车辆叫号，并启动5分钟超时计时；

\2. 调用start_wash_service接口对已叫号的订单启动洗车服务。成功后订单转为washing，从队列中移除该订单，后续订单顺位前移；

\3. 叫号5分钟内仍未启动洗车服务，订单自动转为expired状态，收取10元违约费，计入当日申请次数，系统自动呼叫下一位排队车辆；

\4. 调用end_wash_service接口关闭洗车中的订单，订单转为closed状态，释放工位，自动呼叫下一位排队车辆。

### 3.3.5 洗车服务单状态迁移

洗车服务单有以下5种状态，状态之间的迁移规则如下：

| **状态标识** | **状态名称** | **状态含义**             | **迁移触发条件**                                             |
| ------------ | ------------ | ------------------------ | ------------------------------------------------------------ |
| queuing      | 排队中       | 取号派单成功后进入该状态 | 1. 调用start_wash_service成功，迁移到washing 2. 用户主动取消订单成功，迁移到cancel 3. 叫号超时未到位，或17:30仍排队迁移到expired |
| washing      | 洗车中       | 车辆在工位启动洗车       | 调用end_wash_service成功或时间流逝到18:00迁移到closed        |
| cancel       | 已取消       | 用户主动取消洗车订单     | 时间流逝到18:00迁移到closed                                  |
| expired      | 已过期       | 订单超时未服务           | 时间流逝到18:00迁移到closed                                  |
| closed       | 已结束       | 洗车服务完成或当日归档   | 终态，无后续迁移                                             |

### 3.3.6 队列负载均衡

洗车过程中，管理员可通过trigger_wash_balance接口手动触发全量均衡，调整不同工位排队长度，提高洗车服务效率。单次触发执行一轮完整的三阶段流程，仅调整queuing状态订单，不影响其他状态订单。

**1.【均衡核心原则】**

1）角色选定：从WS1~WS3、WM1~WM2、WL1中选出转出方与接收方；

- Donor（转出方）

\- 队列长度最长的工位

\- 队列长度相同时，工位编号越大，优先转出

- Receiver（接收方）

\- 满足容量条件：当日累计有效订单<20，且当前队列长度<6的工位

\- 队列长度最短的工位

\- 队列长度相同时，工位编号越小，优先接收

2）栈式插入：迁入订单按转移先后逆序排在接收方原始队尾，原队列内部顺序不变；

3）逐级迁移：禁止越级跨组迁移订单，S型订单需经WM组中转，M型订单仅可在WM/WL间迁移，L型订单不跨组；

4）容量约束：每次订单转移后需校验容量，转移后工位排队数≤6、当日累计有效订单≤20，不满足则撤销本次转移；

5）单次触发约束：单次触发仅按顺序执行一轮完整三阶段流程，后面阶段迁移后导致前面结算触发条件满足，不自动处理，等待下一次全量均衡调整。

**2. 【三阶段均衡流程】**

trigger_wash_balance接口触发后，严格按照“组内均衡”→“组间回填”→“组间溢出”的3个阶段进行均衡。

1）阶段1（组内均衡）：WS组内均衡 → WM组内均衡

触发条件：组内工位间队列长度差>1，或等于1但不符合编号越小，队列越长原则。

转移规则：每次从转出方队尾取出1单，按栈式插入规则迁移到接收方，每迁移1单重新校验触发条件。

2）阶段2（组间回填）：（WL→WM回填）→（WM→WS回填）

触发条件：高等级组单工位平均队列长度 - 低等级组 ≥1，且低等级组有可接收容量，且高等级组队尾存在兼容车型订单。

转移规则：每次从转出方队尾取出1条兼容车型订单，按栈式插入规则迁移到接收方，每迁移1单重新校验触发条件。

3）阶段3（组间溢出）：（WS→WM溢出）→（WM→WL溢出）

触发条件：低等级组单工位平均队列长度 - 高等级组 ≥2，且高等级组存在可接收容量。

转移规则：每次从转出方队尾取出1条订单，按栈式插入规则迁移到接收方，每迁移1单重新校验触发条件。

### 3.3.7 洗车收费

洗车结束后，收取洗车服务费用，包含基础洗车费和附加费用。

\1. 洗车基础费：按取号时间对应时段计价。

| **车型** | **平峰时段** | **高峰时段** |
| -------- | ------------ | ------------ |
| S型      | 45元/次      | 50元/次      |
| M型      | 54元/次      | 60元/次      |
| L型      | 72元/次      | 80元/次      |

\- 平峰时段：工作日9:00~12:00、14:00~16:00

\- 高峰时段：工作日12:00~14:00、16:00~18:00；周末、法定节假日全天

\2. 附加费用：取号成功10分钟内取消订单免费，10分钟后取消收取5元手续费；已叫号的订单禁止取消。叫号超时未到工位洗车，收取10元违约费。

\3. 停车时长减免：洗车期间免收停车费，同时减免洗车开始前60分钟至洗车结束后30分钟内的基础停车费，以及洗车期间的停车费；月卡、节假日免费等全免权益生效时，本减免自动失效。

\4. 结算规则：所有洗车费用合并至对应车辆的停车会话账单，出场时一次性结算；优先从会员储值余额扣除，余额不足支持临时支付；营收按支付类型当日分别统计入账、跨天停车的洗车费用计入出场当天收入。

### 4.2.11 查询洗车工位队列

**接口名称**：query_wash_queue(space_id)

**功能说明**：查询指定工位在洗车辆与排队队列；不传参数返回所有工位信息。

| **参数名** | **类型** | **约束说明**                           |

| **返回码** | **输出格式**                                                 | **输出说明**                                              |
| ---------- | ------------------------------------------------------------ | --------------------------------------------------------- |
| E000       | space_id\|washing_order\|[queue1,queue2,queue3,queue4,queue5,queue6] | 查询成功。多工位用分号分隔，无在洗/无排队时对应位置为null |
